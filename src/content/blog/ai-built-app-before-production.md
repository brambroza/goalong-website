ทุกวันนี้เจ้าของธุรกิจหลายคนสร้างระบบต้นแบบได้เองภายในไม่กี่วันด้วยเครื่องมือ AI หน้าจอสวย กดใช้ได้ แต่ระบบที่ "ใช้ได้บนเครื่องเรา" กับระบบที่ "เปิดให้คนจำนวนมากใช้ได้อย่างปลอดภัย" ยังห่างกันอยู่หลายขั้น บทความนี้สรุปสิ่งที่ควรตรวจก่อนเปิดใช้งานจริง

## 1. ความปลอดภัย

โค้ดที่ AI สร้างมักทำงานได้ตามที่ขอ แต่ไม่ได้คิดเผื่อคนที่ตั้งใจเข้ามาโจมตี จุดที่พบบ่อยคือ

- **รหัสผ่านหรือ API key ฝังอยู่ในโค้ดฝั่งหน้าเว็บ** ใครเปิดดูซอร์สก็เห็น
- **ฐานข้อมูลไม่ได้จำกัดสิทธิ์** ผู้ใช้คนหนึ่งเห็นหรือแก้ข้อมูลของคนอื่นได้ เช่น ตั้งค่า Row Level Security ใน Supabase ไม่ครบ
- **ไม่ตรวจข้อมูลที่ผู้ใช้ส่งเข้ามา** เปิดช่องให้ SQL injection หรือฝังสคริปต์
- **ไม่มีการจำกัดจำนวนครั้ง** ทำให้ถูกยิงจนค่าใช้จ่าย API พุ่ง

## 2. การติดตั้งขึ้นใช้งานจริง

- แยกสภาพแวดล้อมทดสอบกับใช้งานจริง ไม่แก้โค้ดบนระบบที่ลูกค้ากำลังใช้
- ตั้งระบบสำรองข้อมูลอัตโนมัติ และ **ทดลองกู้คืนจริงอย่างน้อยหนึ่งครั้ง**
- มีระบบแจ้งเตือนเมื่อเว็บล่มหรือเกิดข้อผิดพลาด
- กำหนดว่าใครมีสิทธิ์เข้าถึงเซิร์ฟเวอร์และบัญชี Cloud

## 3. การเชื่อมกับระบบเดิม

ระบบใหม่มักต้องคุยกับของที่มีอยู่แล้ว เช่น โปรแกรมบัญชี ERP หรือ LINE OA ควรตรวจว่า

- ข้อมูลไหลทางเดียวหรือสองทาง และถ้าข้อมูลไม่ตรงกัน ใครเป็นตัวจริง
- ถ้าการเชื่อมต่อล้มเหลวกลางทาง ระบบจะลองใหม่หรือแจ้งใคร

## 4. การดูแลระยะยาว

ระบบที่สร้างด้วย AI ยังต้องการคนที่เข้าใจโค้ดเมื่อเกิดปัญหา หรือเมื่ออยากเพิ่มฟีเจอร์ ควรมี

- โค้ดอยู่ใน Git และมีคนเข้าใจโครงสร้างทั้งหมด
- เอกสารสั้น ๆ ว่าระบบติดตั้งอย่างไร ใช้บริการอะไรบ้าง
- แผนอัปเดตไลบรารีที่มีช่องโหว่
